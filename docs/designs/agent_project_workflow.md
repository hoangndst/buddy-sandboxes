# Agent Project Workflow

* **Author:** hoangndst
* **Date:** 2026-11-21
* **Status:** Merged (PR #10)

Provider identity, credential storage, and authentication requirements are defined in [User Identity and Brokered Provider Credentials](user_identity_and_provider_credentials.md). That specification supersedes credential behavior described here.

## Problem

`buddy-sbx run` can create a Sandbox and attach the caller's terminal to a process, but it does not interpret a local directory as a workspace. A command such as `buddy-sbx run codex .` currently passes `.` to Codex. The CLI also removes a Sandbox by default when an attached session ends, and its detached mode starts the preset command inside the Pod.

This milestone adds an agent-neutral local-project snapshot workflow on the existing Kubernetes Sandbox and WebSocket exec backend. The agent's own CLI continues to provide the interactive chat interface. Buddy transfers files and terminal input/output; it does not implement another agent UI or sandbox engine.

## User-visible contract

The command accepts:

```text
buddy-sbx run <agent|image> [local-path] [flags] [-- task args...]
```

When `local-path` is present, Buddy packs and uploads a bounded snapshot before starting the agent, sets its working directory to `/workspace`, and synchronizes workspace changes to the local destination when the attached process exits. The path is parsed separately from arguments after `--`. For example, `buddy-sbx run codex . -- "Fix the failing tests"` stages the current directory and passes the prompt to Codex. Agent and custom images must contain `sh`, `mkdir`, `tar`, `mktemp`, `sleep`, and `git`. The Shell preset skips synthetic Git repository initialization, so it can use the stock Ubuntu image.

Provider keys are managed by Buddy and are never forwarded from the CLI host into a Sandbox. Use the credential commands and broker contract in the identity and credential specification linked above.

Attached project runs retain the Sandbox by default. `--rm` requests deletion only after workspace synchronization succeeds. If transfer or merge fails, the CLI retains the Sandbox and reports its ID for recovery. This changes the current default, where runs delete the Sandbox.

`--detach` creates a Sandbox with an idle keeper process, stages a supplied project snapshot, waits for the Sandbox to reach Running, prints its ID, and exits without launching the preset or a task command. The pinned Codex, Claude Code, and Shell images use `/bin/sh -c "sleep infinity"`. A custom image must supply `--idle-command <executable>` and optional repeated `--idle-arg <arg>` values; reject custom-image detach without an idle command before creating the Sandbox. Detached mode rejects `--entrypoint` and all arguments after `--`, because it launches only the keeper process. The command must exist in the image and remain running. If startup fails before the CLI returns, show the Pod/Sandbox failure and delete the failed Sandbox. If the keeper exits later, retain the terminal Sandbox for status and log inspection until explicit deletion or expiry. Detached mode cannot automatically merge later changes because the original process and local baseline are no longer present. Users start a process later with `buddy-sbx exec` and explicitly retrieve files with `buddy-sbx cp`. Reject `--rm` with `--detach`; use `buddy-sbx rm` for explicit cleanup.

`--name` names a newly created Sandbox. A name collision returns a clear error. `exec` starts a new process and does not reattach to a prior agent process. Persistent PTY reattachment, `attach`, and named-Sandbox reuse are outside this milestone.

## Project snapshot and result synchronization

Reuse the streaming tar upload/download endpoints with project-specific archive mapping. Archive entries are workspace-root-relative, so uploading a project places its contents directly in `/workspace`, not `/workspace/<local-basename>`. For downloads, strip and validate the `/workspace` archive root before comparing or writing local paths. Snapshot packing and extraction share one validation policy. Resolve the source path locally; confine destination paths to the chosen project root. Reject traversal, absolute paths, symlinks, hard links, device files, and over-limit archives. Exclude path components `.git`, `.buddy`, `.dev`, `.agents`, `.buddy-sbx-recovery`, `node_modules`, `target`, `dist`, `.next`, `.venv`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, and `.tox`, at any depth. Exclude basenames `.env` and `.env.*`, `.npmrc`, `.pypirc`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, and `id_ed25519*` at any depth. Also exclude `.ssh`, `.aws`, `.azure`, `.kube`, and `.config/gcloud` directory paths at any depth. Matching is case-sensitive; excluded directories are not traversed. The same matcher is used for preview, archive creation, upload validation, and download merge. `.gitignore` does not define this security boundary. After upload, agent images and custom images receive a fresh Git repository in `/workspace` and a baseline commit from staged files using a fixed non-personal identity. The Shell preset omits this Git setup. The agent can use `git status` and `git diff`, but has no host history, branches, remotes, hooks, or Git configuration. Never download the generated `.git` metadata. Snapshot images must contain `sh`, `mkdir`, `tar`, `mktemp`, and `sleep` for transfer and workspace setup; agent images and custom images also need `git`. Report the snapshot size and exclusions before upload. `--preview` prints included and excluded paths and byte/entry counts, and creates no Sandbox.

Use these initial limits: 10,000 archive entries, 100 MiB total regular-file data, 20 MiB per file, 4 KiB per path, and a five-minute transfer deadline. Count directories and files toward the entry limit. On Linux and macOS, preserve ordinary permission bits for regular files and directories; reject setuid, setgid, sticky, device, FIFO, and link entries. On Windows, normalize writable files to `0644`, read-only files to `0444`, and directories to `0755`; only the read-only attribute is representable. The CLI help and README state: “On Windows, Buddy preserves file contents and paths but maps file permissions only to the Windows read-only attribute. POSIX executable bits and group/other permission distinctions are not preserved; directories use normal writable directory permissions.” Keep the limits centralized and covered by tests. The baseline records every path, type, and ordinary permission bits, plus a SHA-256 digest for each regular file. Return additions, edits, and deletions. For each local mutation, compare the destination against the original baseline again immediately before writing. Serialize Buddy sync operations for a project root with an OS file lock stored at `os.UserCacheDir()/buddy-sbx/workspace-locks/<sha256(canonical-root)>.lock`. Create its directory with mode `0700` and lock file with mode `0600`. Canonicalize the root with `Abs`, `EvalSymlinks`, and `Clean`, and normalize case in the lock key on Windows. Acquire the exclusive lock with `TryLock` every 100 ms for at most 30 seconds, honoring cancellation; on timeout, report that another Buddy operation is syncing the project. Hold the lock only while creating the initial archive and while applying the downloaded merge, not while the agent runs. If initial locking fails, abort before Sandbox creation; if merge locking fails, retain the Sandbox and report recovery steps. Do not remove lock files; the OS releases the lock when the process exits, and unlinking can let processes lock different inodes. This coordinates Buddy processes on the same host and filesystem, not separate hosts sharing NFS or SMB. Download to scratch space, then use atomic per-file replacement. Open the selected project once with `os.OpenRoot` and perform snapshot reads, baseline checks, directory creation, temporary-file creation, removal, and rename through root-relative `os.Root` methods. Do not join the absolute project path with remote archive paths for filesystem operations. Convert archive paths to platform-safe local paths and reject traversal, absolute or volume paths, reserved Windows device names, and invalid local paths. Root-relative operations prevent a swapped parent symlink from redirecting writes outside the selected root. `os.Root` does not prevent traversal across mount points or privileged filesystem changes; do not claim protection against local root-level manipulation. On any conflict, preserve local content, save conflicting remote files under `.buddy-sbx-recovery/<sandbox-name>/`, and report conflicting paths; report remote deletion conflicts without deleting the local file. Apply directory changes bottom-up, preserve empty directories, and delete directories only with `os.Remove` after planned child removals; never recursively remove directories, so untracked or excluded children remain. Report that a multi-file merge can be partial if interrupted. A conflict makes synchronization incomplete, so `--rm` must retain the Sandbox. Synchronize output after a nonzero agent exit as well; if synchronization succeeds, the requested `--rm` may still delete the Sandbox, while the CLI returns the agent exit code.

For attached runs, result synchronization happens after the agent process exits and before optional Sandbox deletion. On interruption, use a bounded cleanup context to attempt synchronization. If synchronization fails, retain the Sandbox and print recovery instructions. For detached runs, use explicit `cp`; do not claim automatic merge or synchronization.

## Agent and credential support

Project snapshot and synchronization behavior applies to supported agents that provide an interactive CLI. Provider authentication is specified separately in [User Identity and Brokered Provider Credentials](user_identity_and_provider_credentials.md). The current contract supports Codex with an OpenAI API key and Claude Code with an Anthropic API key. Credentials are stored per Buddy user and scope, encrypted in PostgreSQL, and used by fixed-origin broker adapters. Pods receive a short-lived Sandbox capability, not the provider API key. OAuth and Agy are outside the current provider scope.

## Alternatives weighed

* **Host bind mount or live sync daemon:** Use bounded snapshot transfer because the project directory is on the CLI host, while the Pod may run on a remote node. A bind mount would require a shared node filesystem; continuous sync would add a separate protocol and conflict model.
* **Transfer the host `.git` directory:** Initialize a fresh repository from the staged files. Copying host metadata can expose remotes with embedded credentials, credential helpers, hooks, reflogs, and historical secrets. The tradeoff is that the agent has no original history, branch, remote, or local Git configuration.
* **Pass provider keys into the Pod:** Provider keys stay in the API credential store and are sent only by fixed-origin broker adapters. The Pod receives a short-lived Sandbox capability.
* **General-purpose credential proxy:** Restrict the broker to one provider origin and one Responses API route. A general proxy would let sandbox code select destinations outside the intended provider.
* **Persistent session manager:** Defer `attach` and same-conversation reconnect. The existing WebSocket exec lifetime matches one process invocation; a persistent PTY requires process supervision, durable session identity, and a cross-invocation merge baseline.

## Failure modes

* Invalid local paths, excluded-only projects, archive limits, or unsafe archive entries fail before Sandbox or credential-session creation.
* A missing stored provider credential, insecure non-loopback HTTP credential update, unsupported preset, or direct provider-key injection fails before Sandbox creation.
* Provider capabilities are created as part of authenticated Sandbox creation. Failed or ambiguous creation revokes the pending capability. If creation returns a definitive conflict, preserve the existing Sandbox. For an ambiguous timeout, clean up only when the creation-ID annotation matches; otherwise preserve the resource and report its name.
* Readiness or snapshot upload failure revokes the broker session, captures available Pod diagnostics, and deletes the owned partial Sandbox regardless of `--rm`.
* Broker expiry, budget exhaustion, malformed compressed JSON, unsupported media references, or a gateway restart causes provider requests to fail closed. After an in-memory session loss, the running agent sees a generic provider error; a retained Sandbox requires a new project run to register a new session.
* Agent nonzero exit still attempts result synchronization. A transfer error or local conflict preserves the Sandbox even with `--rm`; a conflict-free sync may honor `--rm`, then the CLI returns the agent exit status.
* CLI interruption attempts bounded session revocation and workspace synchronization. If either cannot complete, the CLI reports the Sandbox name and expiry/recovery path.
* Detached image startup failure reports Pod status and exit diagnostics and deletes the owned failed Sandbox. A keeper that exits after the CLI returns leaves a terminal Sandbox for inspection until explicit deletion or expiry.
* Broker capabilities and encrypted provider credentials are shared through PostgreSQL. Per-process request concurrency and usage estimates do not provide a cluster-wide dollar spending cap.

## API contract and implementation boundary

The project workflow uses the existing authenticated Sandbox, file-transfer, and terminal APIs. User identity, administrator routes, namespace assignment, provider credential storage, provider broker routes, and token lifecycle are specified in [User Identity and Brokered Provider Credentials](user_identity_and_provider_credentials.md). Do not reintroduce the retired `/api/v1/credential-sessions` API or direct provider-key forwarding.

The provider broker supports fixed OpenAI Responses and Anthropic Messages routes. The CLI selects the provider for the `codex` and `claude` presets. Provider API keys are configured separately with `buddy-sbx secret set`; the CLI never copies host environment keys to Sandbox requests.

## Acceptance criteria

1. `buddy-sbx run codex . -- "Fix the failing tests"` parses `.` as the local project path and forwards only the task text to Codex.
2. Attached project runs stage a bounded snapshot, start the agent in `/workspace` through the existing TTY path, and synchronize safe additions, edits, and deletions before returning.
3. Project runs retain the Sandbox by default. `--rm` deletes only after conflict-free synchronization; transfer errors and conflicts preserve the Sandbox and print its ID. Nonzero agent exit still synchronizes output before applying requested cleanup.
4. `--detach` creates an idle Sandbox without starting an agent, stages a project when provided, prints the ID only after startup, and rejects task arguments, `--entrypoint`, and `--rm`. Pinned images use the built-in keeper; custom images require `--idle-command` and optional `--idle-arg` values. Later `exec` and `cp` work as explicit operations.
5. A duplicate `--name` fails clearly. `exec` is documented and tested as a new process, not session reattachment. Broker sessions are revoked on setup failures, attached-run cleanup, explicit `rm`, and Sandbox delete/suspend/terminal events, with the two-hour maximum expiry as a fallback. Ambiguous Sandbox create failures may delete only a resource whose creation-ID annotation matches the invocation.
6. Snapshot tests cover archive root mapping, extraction, exact exclusions and preview parity, fresh Git initialization, baseline comparison, file modes, additions/edits/deletions, conflict recovery, symlink/path rejection, configured limits, interrupted transfers, nonzero agent exits, and cleanup. Broker tests cover middleware separation (CLI token accepted only on management routes, broker token accepted only on the provider route, all other API routes remain protected), live Sandbox cache binding and revocation on delete/suspend/terminal transitions, route and origin restrictions, exact request/response header policy, status and body handling for upstream errors, strict JSON and token-format validation, session isolation by namespace/name/creation ID, streaming, cancellation, compressed/decompressed limits, expiry, revocation on every setup/cleanup path, budget accounting under concurrent reservations, reservation reconciliation and failure charging, restart failure, watch/cache health loss, 15-second refresh cadence, stale-cache denial after 30 seconds, recovery after a successful refresh, and ambiguous-create ownership checks. Workspace tests cover directory modes, empty directories, bottom-up deletion that preserves untracked/excluded children, a local edit during download detected at final recheck, lock contention between processes, lock cancellation/timeout, canonical root aliases, lock release after process exit, and root-confined operations that reject a swapped-ancestor symlink without modifying an outside sentinel. Gateway policy tests cover disabled and enabled label selection without broadening egress, Service and Pod selectors, and KinD port-forward and health-probe behavior. Run `go test ./internal/workspace` on Ubuntu, macOS, and Windows; skip symlink attack setup only when the runner cannot create the required symlink or junction. Test file mode normalization on all three operating systems according to their supported permission semantics.
7. Codex and Claude use their stored user API keys through fixed-origin broker routes. Provider keys never appear in Sandbox or Pod specs, environment, files, logs, or errors. Explicit provider-key `--env` values are rejected. OpenAI OAuth and Agy are outside the current provider scope.
8. The local gateway and operator deploy in KinD. Live verification covers attached Codex or controlled broker traffic without making an unplanned billable request, idle detach, later `exec`, result retrieval, transfer failure recovery, deletion behavior, API-session revocation on Sandbox terminal/deletion, and egress-gateway reachability.
9. Repository quality gates pass, and CLI help/release notes call out persistent-by-default project runs, the detached image contract, and the credential-forwarding compatibility change.

## Deferred work

Importing source history, branches, remotes, or host Git config; persistent agent processes and same-conversation reattachment; `buddy-sbx attach`; named-Sandbox reuse; tmux or another session manager; detached automatic result merging; continuous local directory synchronization; host mounts; additional provider adapters; OAuth credential proxying; a dashboard; autonomous task orchestration; gateway HA; production multi-tenant identity; DNS tunneling enforcement; and mandatory gVisor or microVM runtime support are deferred.

A persistent-session milestone must define process lifetime, terminal reconnect semantics, session cleanup, cross-invocation workspace baselines, and recovery before adding `attach` or named reuse.
