# Agent Project Workflow

* **Author:** hoangndst
* **Date:** 2026-11-21
* **Status:** Draft

## Problem

`buddy-sbx run` can create a Sandbox and attach the caller's terminal to a process, but it does not interpret a local directory as a workspace. A command such as `buddy-sbx run codex .` currently passes `.` to Codex. The CLI also removes a Sandbox by default when an attached session ends, and its detached mode starts the preset command inside the Pod.

This milestone adds an agent-neutral local-project snapshot workflow on the existing Kubernetes Sandbox and WebSocket exec backend. The agent's own CLI continues to provide the interactive chat interface. Buddy transfers files and terminal input/output; it does not implement another agent UI or sandbox engine.

## User-visible contract

The command accepts:

```text
buddy-sbx run <agent|image> [local-path] [flags] [-- task args...]
```

When `local-path` is present, Buddy packs and uploads a bounded snapshot before starting the agent, sets its working directory to `/workspace`, and synchronizes workspace changes to the local destination when the attached process exits. The path is parsed separately from arguments after `--`. For example, `buddy-sbx run codex . -- "Fix the failing tests"` stages the current directory and passes the prompt to Codex. Agent and custom images must contain `sh`, `mkdir`, `tar`, `mktemp`, `sleep`, and `git`. The Shell preset skips synthetic Git repository initialization, so it can use the stock Ubuntu image.

If no local path is provided, command execution remains compatible, but host provider keys are no longer forwarded by default. `--unsafe-forward-provider-key` explicitly opts into that legacy behavior and must display a warning. It is rejected whenever a local path is supplied. Project mode never falls back to direct key forwarding.

Attached project runs retain the Sandbox by default. `--rm` requests deletion only after workspace synchronization succeeds. If transfer or merge fails, the CLI retains the Sandbox and reports its ID for recovery. This changes the current default, where runs delete the Sandbox.

`--detach` creates a Sandbox with an idle keeper process, stages a supplied project snapshot, waits for the Sandbox to reach Running, prints its ID, and exits without launching the preset or a task command. The pinned Codex and Shell images use `/bin/sh -c "sleep infinity"`. A custom image must supply `--idle-command <executable>` and optional repeated `--idle-arg <arg>` values; reject custom-image detach without an idle command before creating the Sandbox. Detached mode rejects `--entrypoint` and all arguments after `--`, because it launches only the keeper process. The command must exist in the image and remain running. If startup fails before the CLI returns, show the Pod/Sandbox failure and delete the failed Sandbox. If the keeper exits later, retain the terminal Sandbox for status and log inspection until explicit deletion or expiry. Detached mode cannot automatically merge later changes because the original process and local baseline are no longer present. Users start a process later with `buddy-sbx exec` and explicitly retrieve files with `buddy-sbx cp`. Reject `--rm` with `--detach`; use `buddy-sbx rm` for explicit cleanup.

`--name` names a newly created Sandbox. A name collision returns a clear error. `exec` starts a new process and does not reattach to a prior agent process. Persistent PTY reattachment, `attach`, and named-Sandbox reuse are outside this milestone.

## Project snapshot and result synchronization

Reuse the streaming tar upload/download endpoints with project-specific archive mapping. Archive entries are workspace-root-relative, so uploading a project places its contents directly in `/workspace`, not `/workspace/<local-basename>`. For downloads, strip and validate the `/workspace` archive root before comparing or writing local paths. Snapshot packing and extraction share one validation policy. Resolve the source path locally; confine destination paths to the chosen project root. Reject traversal, absolute paths, symlinks, hard links, device files, and over-limit archives. Exclude path components `.git`, `.buddy`, `.dev`, `.agents`, `.buddy-sbx-recovery`, `node_modules`, `target`, `dist`, `.next`, `.venv`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, and `.tox`, at any depth. Exclude basenames `.env` and `.env.*`, `.npmrc`, `.pypirc`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `id_rsa*`, and `id_ed25519*` at any depth. Also exclude `.ssh`, `.aws`, `.azure`, `.kube`, and `.config/gcloud` directory paths at any depth. Matching is case-sensitive; excluded directories are not traversed. The same matcher is used for preview, archive creation, upload validation, and download merge. `.gitignore` does not define this security boundary. After upload, agent images and custom images receive a fresh Git repository in `/workspace` and a baseline commit from staged files using a fixed non-personal identity. The Shell preset omits this Git setup. The agent can use `git status` and `git diff`, but has no host history, branches, remotes, hooks, or Git configuration. Never download the generated `.git` metadata. Snapshot images must contain `sh`, `mkdir`, `tar`, `mktemp`, and `sleep` for transfer and workspace setup; agent images and custom images also need `git`. Report the snapshot size and exclusions before upload. `--preview` prints included and excluded paths and byte/entry counts, and creates neither a Sandbox nor a credential session.

Use these initial limits: 10,000 archive entries, 100 MiB total regular-file data, 20 MiB per file, 4 KiB per path, and a five-minute transfer deadline. Count directories and files toward the entry limit. On Linux and macOS, preserve ordinary permission bits for regular files and directories; reject setuid, setgid, sticky, device, FIFO, and link entries. On Windows, normalize writable files to `0644`, read-only files to `0444`, and directories to `0755`; only the read-only attribute is representable. The CLI help and README state: “On Windows, Buddy preserves file contents and paths but maps file permissions only to the Windows read-only attribute. POSIX executable bits and group/other permission distinctions are not preserved; directories use normal writable directory permissions.” Keep the limits centralized and covered by tests. The baseline records every path, type, and ordinary permission bits, plus a SHA-256 digest for each regular file. Return additions, edits, and deletions. For each local mutation, compare the destination against the original baseline again immediately before writing. Serialize Buddy sync operations for a project root with an OS file lock stored at `os.UserCacheDir()/buddy-sbx/workspace-locks/<sha256(canonical-root)>.lock`. Create its directory with mode `0700` and lock file with mode `0600`. Canonicalize the root with `Abs`, `EvalSymlinks`, and `Clean`, and normalize case in the lock key on Windows. Acquire the exclusive lock with `TryLock` every 100 ms for at most 30 seconds, honoring cancellation; on timeout, report that another Buddy operation is syncing the project. Hold the lock only while creating the initial archive and while applying the downloaded merge, not while the agent runs. If initial locking fails, abort before Sandbox creation; if merge locking fails, retain the Sandbox and report recovery steps. Do not remove lock files; the OS releases the lock when the process exits, and unlinking can let processes lock different inodes. This coordinates Buddy processes on the same host and filesystem, not separate hosts sharing NFS or SMB. Download to scratch space, then use atomic per-file replacement. Open the selected project once with `os.OpenRoot` and perform snapshot reads, baseline checks, directory creation, temporary-file creation, removal, and rename through root-relative `os.Root` methods. Do not join the absolute project path with remote archive paths for filesystem operations. Convert archive paths to platform-safe local paths and reject traversal, absolute or volume paths, reserved Windows device names, and invalid local paths. Root-relative operations prevent a swapped parent symlink from redirecting writes outside the selected root. `os.Root` does not prevent traversal across mount points or privileged filesystem changes; do not claim protection against local root-level manipulation. On any conflict, preserve local content, save conflicting remote files under `.buddy-sbx-recovery/<sandbox-name>/`, and report conflicting paths; report remote deletion conflicts without deleting the local file. Apply directory changes bottom-up, preserve empty directories, and delete directories only with `os.Remove` after planned child removals; never recursively remove directories, so untracked or excluded children remain. Report that a multi-file merge can be partial if interrupted. A conflict makes synchronization incomplete, so `--rm` must retain the Sandbox. Synchronize output after a nonzero agent exit as well; if synchronization succeeds, the requested `--rm` may still delete the Sandbox, while the CLI returns the agent exit code.

For attached runs, result synchronization happens after the agent process exits and before optional Sandbox deletion. On interruption, use a bounded cleanup context to attempt synchronization. If synchronization fails, retain the Sandbox and print recovery instructions. For detached runs, use explicit `cp`; do not claim automatic merge or synchronization.

## Agent and credential support

The workspace transfer lifecycle is agent-neutral. Provider authentication is not. The initial implementation supports one brokered provider adapter for Codex. Build a version-pinned Codex image and configure it to send OpenAI API requests to a fixed in-cluster broker. Keep the host OpenAI key in CLI/API gateway memory; the Pod receives only a random, short-lived, Sandbox-scoped token. Require `--allow-api-spend` before a Codex project run may incur model charges, default its Sandbox deadline to two hours, reject longer deadlines, and enforce a server-side usage ceiling and request limits.

Claude and Aider project runs fail before Sandbox creation until equivalent provider adapters are implemented. Shell and custom image runs receive no automatically forwarded provider keys. Project mode rejects explicit `--env OPENAI_API_KEY` and `--env ANTHROPIC_API_KEY` forms, whether written as `NAME` or `NAME=value`. It bypasses preset host-key forwarding entirely. For Codex, append only the broker token as the Pod `OPENAI_API_KEY` after validating all user environment input; the host API key goes only to registration. Other explicit environment values remain caller-authored and may contain secrets. Arbitrary user environment values may still contain secrets; document that limitation. No-path runs require `--unsafe-forward-provider-key` before forwarding the legacy preset provider keys; otherwise they run without those keys. The unsafe flag is rejected in project mode.

The credential API is served by `buddy-api`, the in-cluster REST gateway. Its `StaticTokenAuthenticator` maps each configured CLI bearer token to one Kubernetes namespace and middleware adds that namespace to the request context. Credential session registration and revocation routes derive namespace only from this context and never accept one in a request body, query, or path. Keep these management routes behind the existing static CLI-token middleware. Register only the exact provider endpoint as a separate route in `internal/gateway/server.go` with broker-session middleware, outside the static CLI-token middleware. The route accepts only `POST /api/v1/provider/openai/v1/responses` with no query; all other `/api/v1/*` routes, including credential registration and revocation, remain under CLI-token middleware. That middleware hashes the bearer token, looks up the active `(namespace, sandboxName, creationID)` session, and passes the key-bearing session context only to the provider handler. The provider session token is not accepted by management routes; CLI API tokens are not accepted by the provider route. All other `/api/v1/` paths remain behind the existing static-token middleware. Store sessions by `(namespace, sandboxName, creationID)` and retain only a one-way hash of `sessionToken`; keep the upstream key in process memory. For Sandbox creation, the authenticated gateway stamps the validated creation ID in the reserved annotation `sandboxes.buddy.io/creation-id` and includes it in `GET /api/v1/sandboxes/{name}` responses for ownership verification. This local single-token setup does not provide multi-tenant identity. A namespace-scoped Sandbox informer starts for the configured static-token namespace and must complete initial list/watch sync before broker readiness succeeds. Keep broker readiness separate from general API liveness so a broker cache problem does not remove unrelated API routes from service. Use the informer for prompt state updates and session revocation, but do not treat `HasSynced` as ongoing watch health. On any watch error, mark provider service unhealthy until a successful authoritative full `List` refresh reconciles active sessions and cache state. Run one namespace-scoped full refresh every 15 seconds; provider requests fail closed if initial sync has not completed or the last successful refresh is more than 30 seconds old. A failed refresh leaves provider service unhealthy; a successful refresh can restore it while the watch reconnects. This bounds Kubernetes API work to four list requests per minute per gateway rather than one request per model call. Each provider request checks cached state: the Sandbox exists, its creation ID matches the session, it has no deletion timestamp, it is not suspended, and its phase is `Running`. A delete, suspend, or terminal phase revokes the session. A missing or mismatched object denies provider requests. No token renewal occurs; expiry is capped at two hours and at the requested Sandbox deadline. Use strict JSON decoding: reject unknown fields, duplicate fields, trailing JSON values, and registration bodies over 8 KiB. The revocation route accepts no request body. `sandboxName` must be a valid RFC 1123 label. `sessionToken` is unpadded base64url for exactly 32 random bytes; `creationID` is unpadded base64url for exactly 16 random bytes. `openAIKey` must be nonempty, at most 4 KiB, and contain no control characters or leading/trailing whitespace. Return generic validation errors without echoing submitted values. The credential API is limited to these routes:

* `POST /api/v1/credential-sessions`, authenticated with the existing Buddy API bearer token. The registration body is limited to 8 KiB. The request contains `sandboxName`, random `sessionToken`, random `creationID`, `openAIKey`, and an optional `maxLifetimeSeconds` that can shorten the two-hour maximum; the authenticated namespace is used. Return only the Sandbox name. Reject duplicate sessions and invalid fields without echoing secrets.
* `DELETE /api/v1/credential-sessions/{sandboxName}/{creationID}`, authenticated with the existing Buddy API bearer token and idempotent. Revoke only the matching session and return no content whether it existed or not.
* `POST /api/v1/provider/openai/v1/responses` with no query string, authenticated with the registered session token as bearer. Bind each session to one `(namespace, sandboxName)`, replace the token with the stored key, and forward only to `https://api.openai.com/v1/responses` through the egress gateway. Reject redirects, other methods, paths, origins, and payloads containing image, audio, or file references. Construct upstream request headers from this allowlist only: `Content-Type: application/json`; `Accept` with either `text/event-stream` or `application/json`; `User-Agent`; `originator`; `x-client-request-id`; `session-id`; `thread-id`; `x-openai-subagent`; `x-codex-beta-features`; `x-codex-turn-state`; and `x-codex-routing-hint`. Replace Authorization with the stored key, set Host from the fixed origin, and never forward Host, Cookie, Proxy-Authorization, `x-api-key`, Connection or other hop-by-hop headers, arbitrary `x-*`, or forwarded headers. Add another header only if it is observed in the pinned Codex build and covered by an integration test. Support only identity and zstd `Content-Encoding`; cap compressed request bytes at 512 KiB and decompressed JSON at 4 MiB, then decompress before applying JSON limits or usage accounting and forward uncompressed. Reject malformed or unsupported encodings. The HTTP transport sets Content-Length.

The pinned Codex build is `@openai/codex@0.171.0`, installed in a `node:22-bookworm-slim` image pinned to multi-platform index digest `sha256:e9f565d32859f0cbfb52125eafe8be39390f24dac302dc3cdf566e8ba3ab21ee`. The image config sets model `gpt-6.2-sol`, custom provider base URL `http://buddy-api.buddy-sandboxes-system.svc:8080/api/v1/provider/openai/v1`, `env_key = "OPENAI_API_KEY"`, Responses wire API, and disables WebSocket transport. The broker accepts only model `gpt-6.2-sol`; a different or missing model is rejected. The image launcher writes this fixed config into the mounted home volume before starting Codex. The repository image name is `ghcr.io/hoangndst/buddy-sandboxes-codex:0.171.0`; publish this version once and do not overwrite its tag. The broker streams both directions and propagates cancellation. Cap upstream responses at 16 MiB, allow four concurrent calls and ten request starts per minute per session, use a 60-second idle timeout and 15-minute total timeout, and limit `max_output_tokens` to 8,192. Each session expires no later than two hours after registration, with no renewal, and has a 1,000,000-token cumulative ceiling. A Codex project Sandbox defaults to `--duration=2h`; a shorter requested duration shortens the session lease, and a longer duration is rejected. Before forwarding, estimate input tokens as the decompressed request-body byte count and reserve that amount plus the enforced 8,192-token output limit. Under a per-session lock, atomically reject if used tokens plus outstanding reservations plus this reservation would exceed 1,000,000. On a completed response with valid reported usage no greater than the reservation, release the reservation and charge actual usage. On an upstream error, cancellation, incomplete stream, or missing or malformed usage, charge the full reservation. If reported usage exceeds the reservation, mark the session exhausted and record an accounting violation without releasing the excess. This keeps concurrent calls within the ceiling under the input-byte estimate and output-limit assumptions. This is a token ceiling, not a dollar limit. Stream upstream status and body unchanged for 4xx, 429, and 5xx responses, subject to the response-size cap; do not wrap them in a success response. Reject any 3xx response as a generic 502 without forwarding `Location`. Forward only `Content-Type`, `Cache-Control`, `Retry-After`, `x-request-id`, `openai-processing-ms`, `x-ratelimit-*`, and `x-codex-turn-state`; do not pass `Set-Cookie`, `Location`, hop-by-hop, or arbitrary headers. Flush streaming chunks. Do not log keys, authorization headers, request or response bodies, or upstream error bodies. The broker is not a general-purpose proxy. For Codex project runs, generate the Sandbox name, random session token, and creation ID before creating the Sandbox; register the session before Pod startup; pass only the broker URL and session token to the Pod; upload the workspace after the Sandbox reaches Running; then start Codex. After registration succeeds, keep a cleanup guard active. Before session registration, look up a caller-supplied name and fail clearly if it already exists. On a definitive create conflict, revoke the session but never delete by name. If create times out ambiguously, revoke the session and query the Sandbox: delete only when its creation ID annotation matches this run. If the API is unavailable or the marker is absent or different, preserve the Sandbox and report its name for inspection. After a confirmed create, readiness failure, upload failure, or interruption before agent start, collect diagnostics and delete the owned Sandbox regardless of `--rm`. Report every cleanup failure and the Sandbox name. These setup failures always clean up because no useful run has started. On exit, revoke the session and synchronize the workspace independently under a fresh bounded cleanup context; delete only after conflict-free synchronization when `--rm` was requested. `buddy-sbx rm` also attempts session revocation before deleting the Sandbox. If revocation is unavailable, report the Sandbox ID/name and that the maximum two-hour session expiry is the fallback. Deploy a single-replica local `buddy-api` Service and Deployment with a `Recreate` strategy and generated non-default authentication material. The gateway reads `BUDDY_API_TOKEN` and `BUDDY_API_NAMESPACE` from its environment; the Deployment sources the token from Secret `buddy-api-token`, key `token`, and maps it to namespace `default`. ## Alternatives weighed

* **Host bind mount or live sync daemon:** Use bounded snapshot transfer because the project directory is on the CLI host, while the Pod may run on a remote node. A bind mount would require a shared node filesystem; continuous sync would add a separate protocol and conflict model.
* **Transfer the host `.git` directory:** Initialize a fresh repository from the staged files. Copying host metadata can expose remotes with embedded credentials, credential helpers, hooks, reflogs, and historical secrets. The tradeoff is that the agent has no original history, branch, remote, or local Git configuration.
* **Pass provider keys into the Pod:** Use a broker for Codex project runs and require an explicit unsafe flag for legacy no-path forwarding. Workspace code can read Pod environment values, so direct forwarding is not the project-mode credential path.
* **General-purpose credential proxy:** Restrict the broker to one provider origin and one Responses API route. A general proxy would let sandbox code select destinations outside the intended provider.
* **Persistent session manager:** Defer `attach` and same-conversation reconnect. The existing WebSocket exec lifetime matches one process invocation; a persistent PTY requires process supervision, durable session identity, and a cross-invocation merge baseline.

## Failure modes

* Invalid local paths, excluded-only projects, archive limits, or unsafe archive entries fail before Sandbox or credential-session creation.
* Missing OpenAI key or `--allow-api-spend`, insecure non-loopback HTTP, unsupported Codex preset, or known direct provider-key injection fails before Sandbox creation.
* Credential registration failure prevents Sandbox creation. If creation returns a definitive conflict, preserve the existing Sandbox. For an ambiguous timeout, clean up only when the creation-ID annotation matches; otherwise preserve the resource and report its name.
* Readiness or snapshot upload failure revokes the broker session, captures available Pod diagnostics, and deletes the owned partial Sandbox regardless of `--rm`.
* Broker expiry, budget exhaustion, malformed compressed JSON, unsupported media references, or a gateway restart causes provider requests to fail closed. After an in-memory session loss, the running agent sees a generic provider error; a retained Sandbox requires a new project run to register a new session.
* Agent nonzero exit still attempts result synchronization. A transfer error or local conflict preserves the Sandbox even with `--rm`; a conflict-free sync may honor `--rm`, then the CLI returns the agent exit status.
* CLI interruption attempts bounded session revocation and workspace synchronization. If either cannot complete, the CLI reports the Sandbox name and expiry/recovery path.
* Detached image startup failure reports Pod status and exit diagnostics and deletes the owned failed Sandbox. A keeper that exits after the CLI returns leaves a terminal Sandbox for inspection until explicit deletion or expiry.
* Gateway session state is in memory and single-replica. A restart drops active registrations and quota counters; requests fail closed, and the maximum two-hour session expiry is the fallback if explicit revocation or watch-driven revocation cannot complete.

## Acceptance criteria

1. `buddy-sbx run codex . -- "Fix the failing tests"` parses `.` as the local project path and forwards only the task text to Codex.
2. Attached project runs stage a bounded snapshot, start the agent in `/workspace` through the existing TTY path, and synchronize safe additions, edits, and deletions before returning.
3. Project runs retain the Sandbox by default. `--rm` deletes only after conflict-free synchronization; transfer errors and conflicts preserve the Sandbox and print its ID. Nonzero agent exit still synchronizes output before applying requested cleanup.
4. `--detach` creates an idle Sandbox without starting an agent, stages a project when provided, prints the ID only after startup, and rejects task arguments, `--entrypoint`, and `--rm`. Pinned images use the built-in keeper; custom images require `--idle-command` and optional `--idle-arg` values. Later `exec` and `cp` work as explicit operations.
5. A duplicate `--name` fails clearly. `exec` is documented and tested as a new process, not session reattachment. Broker sessions are revoked on setup failures, attached-run cleanup, explicit `rm`, and Sandbox delete/suspend/terminal events, with the two-hour maximum expiry as a fallback. Ambiguous Sandbox create failures may delete only a resource whose creation-ID annotation matches the invocation.
6. Snapshot tests cover archive root mapping, extraction, exact exclusions and preview parity, fresh Git initialization, baseline comparison, file modes, additions/edits/deletions, conflict recovery, symlink/path rejection, configured limits, interrupted transfers, nonzero agent exits, and cleanup. Broker tests cover middleware separation (CLI token accepted only on management routes, broker token accepted only on the provider route, all other API routes remain protected), live Sandbox cache binding and revocation on delete/suspend/terminal transitions, route and origin restrictions, exact request/response header policy, status and body handling for upstream errors, strict JSON and token-format validation, session isolation by namespace/name/creation ID, streaming, cancellation, compressed/decompressed limits, expiry, revocation on every setup/cleanup path, budget accounting under concurrent reservations, reservation reconciliation and failure charging, restart failure, watch/cache health loss, 15-second refresh cadence, stale-cache denial after 30 seconds, recovery after a successful refresh, and ambiguous-create ownership checks. Workspace tests cover directory modes, empty directories, bottom-up deletion that preserves untracked/excluded children, a local edit during download detected at final recheck, lock contention between processes, lock cancellation/timeout, canonical root aliases, lock release after process exit, and root-confined operations that reject a swapped-ancestor symlink without modifying an outside sentinel. Gateway policy tests cover disabled and enabled label selection without broadening egress, Service and Pod selectors, and KinD port-forward and health-probe behavior. Run `go test ./internal/workspace` on Ubuntu, macOS, and Windows; skip symlink attack setup only when the runner cannot create the required symlink or junction. Test file mode normalization on all three operating systems according to their supported permission semantics.
7. Codex project mode requires `--allow-api-spend`; it defaults to a two-hour deadline and rejects longer requests; the broker never places the host API key in Sandbox or Pod specs, environment, files, logs, or errors. Shell/custom images receive no host provider credentials; project mode rejects explicit `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` values; Claude/Aider project mode fails before Sandbox creation. Legacy no-path provider runs require the explicit `--unsafe-forward-provider-key` flag.
8. The local gateway and operator deploy in KinD. Live verification covers attached Codex or controlled broker traffic without making an unplanned billable request, idle detach, later `exec`, result retrieval, transfer failure recovery, deletion behavior, API-session revocation on Sandbox terminal/deletion, and egress-gateway reachability.
9. Repository quality gates pass, and CLI help/release notes call out persistent-by-default project runs, the detached image contract, and the credential-forwarding compatibility change.

## Deferred work

Importing source history, branches, remotes, or host Git config; persistent agent processes and same-conversation reattachment; `buddy-sbx attach`; named-Sandbox reuse; tmux or another session manager; detached automatic result merging; continuous local directory synchronization; host mounts; additional provider adapters; OAuth credential proxying; a dashboard; autonomous task orchestration; gateway HA; production multi-tenant identity; DNS tunneling enforcement; and mandatory gVisor or microVM runtime support are deferred.

A persistent-session milestone must define process lifetime, terminal reconnect semantics, session cleanup, cross-invocation workspace baselines, and recovery before adding `attach` or named reuse.
